# 虚拟分组（1.6.0）

盒子现在保存项目的原路径，文件、文件夹和快捷方式留在原处。拖入、跨组拖动、组内排序、按类型整理、移出分组和解散分组都不搬动或删除原文件。组内双击仍打开原项目，右键可定位原文件。

## 使用

- 拖入任意位置的文件或快捷方式，只增加分组关系；同一原路径只归属一个组，不同目录的同名文件可以共存。悬停可查看完整路径。
- 跨组拖动改变归属，组内拖动调整顺序；从分组拖到 Explorer 仅允许复制/创建链接，原项目继续保留。移出分组请用右键“移出分组”。
- 系统图标直接记录 Shell 解析名，不额外创建 `.lnk`。既有系统图标快捷方式仍可继续使用。
- 设置 → 整理 → “按类型分组桌面项目”包含用户桌面和公共桌面，仅处理尚未归组的项目；快捷方式和程序是否自动归组由原有开关控制。
- “撤销上次整理”只撤销本次增加的关系，保留之后手动进行的跨组调整。升级前的物理整理记录仍按原位置撤销，同名冲突不会覆盖文件。
- 原桌面图标保留 Windows 的显示行为。想只看分组时，在设置 → 图标关闭“同时隐藏分组”，再双击桌面空白处隐藏原图标。原有默认开关保持不变。

## 旧盒子转换与持久化

首次启动对旧文件夹做一次内容快照，将文件名顺序转换为完整路径顺序，并保留盒子 ID、标题、位置、尺寸、折叠/锁定/视图状态。原文件夹和所有内容保留，不把文件迁回桌面。目录离线或无法枚举时保留旧记录，稍后重试，避免误转换成空组。

配置模式为 `Version=2`，每个虚拟组包含 `IsVirtual=true`、`Entries`（原路径，系统项目另存显示名）及完整路径 `ItemOrder`。旧 `Folder` 仅保留原内容位置；新虚拟组不创建存储文件夹。以后直接往旧文件夹新增文件，不会自动建立新分组关系，需要再拖入分组。

后续启动从配置恢复布局与引用，不再扫描旧盒子内容。继续使用原图标内存缓存和磁盘 PNG 缓存，原路径不变可以沿用缓存。目录监听延后安装；文件被外部重命名会同步引用和顺序，文件暂不可用时保留引用、显示提示，目录恢复后重新连接监听。OneDrive 桌面重定向恢复也同步子项引用。
