# 桌面整理（离线自用版）功能规格

> 文档性质：**净室需求文档**。本文只描述「软件对外表现出的功能行为」，不涉及任何反编译代码、不参考原实现。
> 版权只保护表达、不保护思想与原理，因此基于本文独立写出的代码是你自己的作品。
> 参考对象：腾讯桌面整理 DeskGo 4.2.1624.127 lite 版；行为描述来自官方产品页与公开使用教程。

## 0. 范围界定

目标：做一个**纯本地、不联网、无账号**的桌面整理工具，覆盖原软件中离线可用的全部核心能力。

排除：账号与同步、云盘、魔镜壁纸、在线更新、数据上报、管家捆绑与推广、论坛/用户心声。

注：`lite` 版本身就是去掉魔镜壁纸的精简版，所以本规格描述的范围与 lite 版的定位一致。

## 2. 纳入功能的详细规格

优先级：P0 = 没有它产品不成立；P1 = 明显影响可用性；P2 = 锦上添花。

### A. 桌面分区盒子

#### A1 一键整理（P0）

- 在桌面空白处右键 → 「一键整理」，把桌面上的图标自动分类归入若干预设盒子。
- 分类维度：按文件类型分组，典型分组为文档、图片、视频、音乐、压缩包、文件夹、其他。
- 关键行为：**只有文件与文件夹被自动归类；可执行程序与快捷方式不自动归类**，需要用户手动拖入（这是公开教程中明确描述过的行为差异）。
- 整理后原始文件的实际存储位置不变，只是显示被收进盒子。

#### A2 盒子的创建与编辑（P0）

- 桌面右键 → 「新建盒子」创建一个空盒子。
- 双击盒子标题 → 重命名。
- 拖拽盒子任意位置 → 移动；拖拽边框/角 → 改变大小。
- 盒子删除后，其中的文件回到桌面散落显示，**不得删除或移动真实文件**。
- 盒子内的图标支持两种视图：大图标 / 列表，可切换。

#### A3 盒子外观（P1）

- 半透明背景、圆角、标题栏与图标网格。
- 可调：底色/透明度、标题栏是否显示、图标尺寸、是否显示滚动条。
- 折叠 / 展开（折叠后只留标题栏）。
- 盒子可设置始终置顶与否。

#### A4 拖拽与文件操作（P0）

- 从桌面（或资源管理器）拖文件进盒子 → 加入该盒子。
- 从盒子拖出到桌面 → 移出盒子。
- 盒子之间拖动 → 转移归属。
- 盒子内右键图标 → 至少支持：打开、打开文件所在位置、重命名、删除。
- 盒子内选中多个后整体拖动。

#### A5 滚动（P1）

- 盒子内容超出边界时，滚轮滚动，可切换为无滚动条形态。

#### A6 锁定（P1）

- 盒子可锁定，锁定后不能被拖动和缩放，防止误操作。

#### A7 持久化（P0）

- 盒子数量、位置、尺寸、名称、外观设置、每个盒子包含哪些文件，全部落地到本地配置文件（建议 JSON）。
- 配置文件放在**程序旁边**（绿色便携，程序放哪配置就跟到哪）；老位置 `%APPDATA%\JianZhuo\` 的配置在第一次运行新版本时自动迁移。程序目录不可写时回退到 `%APPDATA%\JianZhuo\`。
- 重启后完整还原。
- 被整理的文件在外部被删除/改名后，启动时做一次存在性校验并清理失效条目，不能让盒子崩溃或丢数据。
- 配置文件损坏时回退到备份，不能因为读配置失败就清空用户桌面布局。

#### A8 盒子排布：自动对齐与避免重叠（P1）

桌面上摆了多个盒子之后，手动对齐费劲，需要工具帮忙。这是两个独立开关：

- **自动对齐**：拖动某个盒子时，如果它的边（左/右）或中线、上/下边或中线距离另一个盒子的对应位置在 8px 以内，就吸附过去，并显示一条贯穿两个盒子的参考线；涉及的两个轴各自独立判断。
- **避免重叠**：拖动过程本身不受限制（允许压着别的盒子拖过去），但**松手落位时**如果与任何盒子重叠，就自动移动到离松手位置最近的空位；候选位置由其他盒子的边推导，因此落点总是贴着某个盒子，而不是随机漂移；范围限制在盒子当前所在的区域内，不会因为避让把它甩到别的显示器。
- **不出屏**：盒子边缘不会被拖到屏幕之外——往屏幕外拖时会自动停在距屏幕边缘 12px 的位置（和两个盒子之间的间距同一数值）；往内拖回来照常跟随鼠标。换个显示器布局或改了分辨率之后启动，配置里落在屏幕外的坐标也会先被拉回屏幕内。缩放盒子时同理。
- 「仅仅贴边」不算重叠，所以吸附对齐出来的相邻盒子不会被避让逻辑再推开。
- 新建盒子时同样避让，避免新盒子正好盖在已有盒子上。
- 两个开关都能在设置面板里关掉。

#### A9 盒子里的条目拖动：排序与跨盒子（P1）

- **盒内排序**：在盒子里按住某一条拖到别的位置，松手后条目按落点重新排列，拖动过程中在落点位置显示一条插入提示线。只调整显示顺序，**不会动磁盘上的文件**。
- **跨盒子移动**：把条目拖到另一个盒子上松手，文件会真的移动到那个盒子对应的文件夹里，并落在松手的位置；反过来，从资源管理器往盒子里拖文件也同样落在落点位置。
- 顺序记在盒子配置的 `ItemOrder` 里（只存文件名，跟着盒子一起保存）。新放进盒子的条目不在记录里，排在已记录顺序的后面，按默认规则（文件夹优先、再按名称）排序。
- 按住左键移动超过 6px 才算拖动，单纯点击只做选择，不会误触发拖动。

#### A10 盒子缩放：按图标格子顿挫（P1）

- 条目在图标视图里是固定大小的格子（宽 = 图标 + 内边距 + 名称区，高固定两行文字），因此盒子可以按格子缩放。
- 拉左右边框：宽度只按**整列**跳，并同时按条目总数把高度收成刚好放下的**行数**——3 列 × 4 行（12 项）往右拉一列就变成 4 列 × 3 行，盒子自己变矮。拉上下边框：高度只按**整行**跳，宽度不变。拖左边 / 上边时，对边固定不动。
- 格子尺寸与「留白」（标题栏、边框、内边距）在**按下缩放条时量一次**，整段拖动都用这一份，否则每移动一下都按新尺寸重算，框会越拖越漂。
- 列表视图没有列概念：宽度自由，只有高度按行顿挫。
- 缩放热区（边框 6px 的条、四角 14px）落在不透明的框体上——盒子是分层窗口，阴影区（透明像素）收不到鼠标消息，热区放在那里会抓不住。

### B. 桌面图标显示控制

#### B1 双击桌面空白处隐藏/显示图标（P0）

- 在桌面空白区域双击 → 所有桌面图标（含所有盒子）隐藏；再双击 → 恢复。
- 隐藏状态在重启后保持。
- 与系统「显示桌面图标」开关互不干扰。

#### B2 显示/隐藏桌面图标（P1）

- 提供显式开关，等价于系统右键「查看 → 显示桌面图标」，但要在不破坏系统设置的前提下实现（推荐走系统 Shell 状态，而不是自己模拟）。

#### B3 图标自动排列（P2）

- 提供对齐网格、自动排列的开关，行为与系统同名选项一致。

### C. 右键菜单集成

#### C1 桌面空白处菜单（P0）

- 菜单项：一键整理、新建盒子、（可选）显示/隐藏桌面图标、（可选）整理设置、退出。

#### C2 资源管理器菜单（P1）

- 对选中的文件/文件夹提供「整理到盒子」入口。
- 采用 Shell 扩展（`IExplorerCommand` / 注册表菜单）实现，注意 Win11 只会在「显示更多选项」中出现。

### D. 磁盘映射

#### D1 把磁盘目录映射到桌面（P1）

- 选择一个磁盘上的目录，在桌面上生成一个映射入口，双击直达该目录。
- 用途是"释放 C 盘空间"：把大文件夹搬到别的盘，再在桌面留一个入口。
- 建议做成真正的 `.lnk` 快捷方式或独立的小图标层，**不要用符号链接/目录联接**（自用场景下更安全，不需要管理员权限，也不会因为误删产生连锁影响）。
- 支持删除映射入口，且删除入口不影响源目录。

### E. 全盘文件搜索

#### E1 搜索入口（P1）

- 提供一个呼出方式：桌面右键菜单 / 全局快捷键 / 托盘菜单，弹出搜索框。
- 输入关键词 → 实时返回匹配的本地文件与文件夹。

#### E2 匹配能力（P1）

- 支持文件名子串匹配、不区分大小写。
- 支持拼音首字母匹配（中文文件名场景下的刚需）。
- 支持按类型/时间/大小过滤（可后置）。

#### E3 结果操作（P1）

- 回车打开、右键 → 打开所在位置、复制完整路径。

#### E4 索引实现（P1）

- 方案一（推荐，纯离线、快）：读取 NTFS 的 MFT / USN Journal 构建本地索引，只索引文件名，增量维护。
- 方案二（简单但慢）：用 `FindFirstFileEx` 遍历并缓存，首建索引时避开系统目录。
- 索引数据只存本地，绝不外传。

### F. 程序外壳

#### F1 托盘（P0）

- 托盘图标，右键菜单：打开设置、暂停整理、退出。
- 支持显示/隐藏托盘提示（气球消息）。

#### F2 设置界面（P0）

- 常规：开机自启、双击隐藏图标、托盘行为。
- 外观：盒子默认样式、透明度、图标大小。
- 盒子管理：列出已有盒子，可删除/重置。
- 搜索：索引范围、排除目录、重建索引。
- 关于：版本号、第三方开源许可列表。

#### F3 开机自启（P1）

- 写入 HKCU 的 `Run` 键，必须支持一键取消，不能残留。

### G. 非功能要求

- **完全离线**：任何功能都不依赖网络；程序内不存在联网代码路径。
- **数据安全**：整理只是改变"显示归属"，任何操作都不得静默移动或删除用户文件；所有破坏性操作先给确认。
- **稳定性**：不能被系统或安全软件判定为注入/劫持（这与实现方式强相关，见下节）。
- **资源占用**：常驻内存目标 < 80MB，空闲 CPU 接近 0。
- **多显示器与不同 DPI**：盒子位置按显示器分别持久化，缩放变化时不乱序。
- **崩溃恢复**：进程崩溃后重启，桌面布局必须能还原。

## 3. 实现路径提示（我们自己的设计，非原实现）

桌面整理类工具的技术难点集中在"如何把窗口贴在桌面上、又如何接管桌面图标"。可选路线：

1. **自绘盒子路线（推荐）**：不碰系统的桌面图标列表，自己创建无边框分层窗口（`WS_EX_LAYERED | WS_EX_TOOLWINDOW`），把它们挂到桌面窗口（`Progman` / `WorkerW`）之下作为子窗口。盒子内容由自己绘制，拖拽用 `IDropTarget`。
   - 优点：不需要注入 explorer，不会被杀软误报，Win10/Win11 行为稳定。
   - 代价：桌面原有图标仍需用系统开关或 Shell API 隐藏，视觉上要自己对齐网格。
   - 实测（Windows 11，2560×1440）：把**分层窗口**（`WS_EX_LAYERED`，即 WPF `AllowsTransparency=true`）`SetParent` 到 `Progman` 之后**完全不会被渲染**（补 `WS_CHILD` 也一样），而非分层窗口能显示。所以透明盒子走不了"挂成桌面子窗口"这条路，只能保持顶层窗口：Win+D 时改为把桌面窗口压回 z 序底层（抬高盒子自身无效，受 z 序带限制），并拦掉 `SC_MINIMIZE`。
2. **接管系统图标列表路线**：把 `SHELLDLL_DefView` 里的 `SysListView32` 消息钩子接管，实现"拖进盒子"的物理移动。
   - 优点：图标渲染、拖拽、右键菜单全部复用系统，体验最像原版。
   - 代价：跨进程子类化，需要处理 explorer 重启、权限、杀软误报，维护成本高。

推荐先用路线 1 做出可用的 P0 闭环，路线 2 作为后续增强。

技术栈建议：C# + WPF/WinUI（开发快，`P/Invoke` 足够），或 C++ + Qt（体积小、更接近原版手感）。

## 4. 待你确认的行为细节

以下行为在公开资料中描述得不一致，需要在真机上观察后再定稿：

1. 「一键整理」是否会把**已安装程序的快捷方式**归类，还是只在盒子中排除可执行文件本身。
2. 盒子内删除文件时，是直接删除还是移入回收站。
3. 隐藏桌面图标时，盒子本身是否也随之隐藏（还是只隐藏散落图标）。
4. 盒子内图标的排序规则：是否沿用桌面排序，还是各自独立、可自定义。
5. 磁盘映射入口是快捷方式文件还是独立的虚拟图标。

## 5. 下一步

按 P0 拆成三个阶段：

1. **阶段一**：程序外壳 + 盒子创建/移动/缩放/重命名 + 配置文件持久化。
2. **阶段二**：拖拽进出盒子 + 一键整理自动分类 + 双击隐藏桌面图标。
3. **阶段三**：右键菜单、磁盘映射、全盘搜索、设置界面完善。

阶段一完成即为可用产品。
