# 登录自启排查（2026-11-03）

基线：main `aaf2ad2`，正式版 v1.5.2，现有 5 个盒子。此次只更新诊断工具，不替换运行程序、不修改配置、自启项或盒子文件，不决定分区架构。

## 已确认的原因

当前账户是内置 Administrator（用户 SID 最后一段为 `500`），DeskBox 与诊断 PowerShell 均以未提升权限的中等完整性运行。Schedule 服务正常，`Schedule.Service.Connect`、打开根任务目录、创建任务定义和触发器均成功；`RegisterTaskDefinition` 返回 `0x80070005 / E_ACCESSDENIED`。

[微软任务安全上下文文档](https://learn.microsoft.com/en-us/windows/win32/taskschd/security-contexts-for-running-tasks)明确说明：低权限进程不能为内置 Administrator 注册任务；该账户的任务忽略 `RunLevel`，提升权限注册后也会提升权限运行。因此仅设置 `RunLevel=0` 不能修复本机情况，不能把“一次提权注册”直接当成不影响运行权限的解决方案。

用禁用且不执行的独立临时任务复现：

| 变体 | 结果 |
| --- | --- |
| 当前实现：用户名触发器、隐式当前用户 principal | 注册拒绝访问 |
| 触发器改用户 SID | 注册拒绝访问 |
| principal 和注册参数显式传当前 SID | 注册拒绝访问 |
| 移除全部触发器 | 注册拒绝访问 |
| 兼容模式 1.0 / 2.0 | 注册拒绝访问 |
| 独立任务文件夹 | 文件夹可创建，任务仍拒绝访问 |

探针结束已清理临时文件夹；注册失败未留下临时任务。正式 `DeskBox` 任务不存在，当前自启仍为 `HKCU\Software\Microsoft\Windows\CurrentVersion\Run\DeskBox`，指向 `dist\DeskBox.exe --startup`。没有证据说明是路径、SID 格式或任务目录权限导致本次失败；其他账户/机器的拒绝访问仍需单独检查。

## 可重复检查

在仓库根目录运行，默认只读，不弹 UAC：

```powershell
pwsh -File tools/diagnose-autostart.ps1
pwsh -File tools/diagnose-autostart.ps1 -ProbeRegistration
pwsh -File tools/verify-boot-timing.ps1
```

第二条只注册禁用的 GUID 临时任务，使用 `TASK_CREATE` 防止覆盖，成功注册后在 `finally` 删除。不执行任务、不更改正式自启项。

## 测量口径

- 最新普通程序重启样本为 2026-11-03 14:27：5 个盒子首帧分别为进程创建后 1151、1152、1152、1153、1153ms。Explorer 当时已运行约 5 小时 22 分钟，不能代表开机冷启动或登录耗时。
- 现有日志的绝对时间戳只有秒精度；原脚本把它当毫秒精度再减入口耗时，会引入最多约 1 秒误差。
- 原脚本只取入口后 40 行，可能漏掉首帧；最新模块入口也可能只是单实例转发/自检。现在选取最近一次确有盒子首帧的启动段，统计首个与最后一个首帧，并核对配置盒子数。
- 原脚本会把第一条 Run 枚举事件当作桌面切换，这是错误的。现在仅列出当前 Explorer 启动后、当前用户的相关原始事件；没有明确登录/桌面切换证据时，保持登录耗时未知。
- `ContentRendered` 只证明盒子首帧，不证明全部图标已绘制。需结合图标批次/预热日志及实际观察验证“完整分区和图标”。

## 下一步边界

先确定本机可接受的启动权限方案，再做同一次真实登录的端到端采样。若采用内置 Administrator 的提升权限任务，必须验证 Explorer 到盒子的拖拽、在线更新以及运行期权限影响。普通用户账户可验证最低权限登录任务，但此次未切换账户或更改系统策略。

继续保留 HKCU Run 作为当前可用回退。虚拟分组与 Explorer 原生图标分区仍是待比较方案；它们不能修复进程尚未被启动的等待时间，应在启动时机与程序内显示耗时分别测清后再决定。
